# Glyph v0.1.5 Release Notes

Glyph v0.1.5 expands application management with real icon-theme browsing, accurate multi-distribution package provenance, host-aware application launching, command customization, safe AppImage discovery and lifecycle management, and informational install/update guidance.

---

## What's New

### 🎨 Installed Icon Theme Browser & Picker
- Browse icons from all installed desktop icon themes directly from an application's detail panel.
- Filter theme icons with instant search and browse across theme categories.
- **Theme Icon vs. Fixed Artwork Choice**:
  - **Theme Icon**: Customizes the launcher using the icon's semantic name, allowing the icon to adapt dynamically whenever you switch your desktop icon theme.
  - **Fixed Artwork**: Copies the resolved image file into Glyph's local storage so the icon remains fixed regardless of desktop theme changes.
- Falls back gracefully to standard image file selection if custom artwork is preferred.

### 🏷️ Package Classification & Version Provenance
- High-fidelity package classification recognizing **RPM**, **Flatpak**, **DEB**, **Pacman**, **Snap**, and **AppImage**.
- Clear scope indicators distinguishing between **System** and **User** installations.
- Version provenance displayed on application detail views with truthful origin tracking (e.g., distro package manager database or Desktop Entry specification).
- Fast, batch-primed system queries (utilizing Python RPM TransactionSet bindings and system package tools) ensuring the catalog stays instantaneous.

### 🚀 Unified Application Launch Service
- Complete launch parity across native environments and Flatpak builds.
- Native launches use GIO DesktopAppInfo with safe argv fallback.
- Flatpak builds invoke external applications through host spawning adapters (`flatpak-spawn --host gtk-launch <desktop-id>`), running as the logged-in host user via the `org.freedesktop.Flatpak` session bus capability, with clear, actionable error feedback when launch fails. (Note on sandboxing: this permission enables arbitrary command execution as the host user and is an accepted trust tradeoff, not an isolation boundary if the application were compromised).
- Command lines strip specification field codes (`%f`, `%u`, `%k`, etc.) safely.

### ✏️ Custom Launch Command Editor
- Customize any application's launch command directly from the detail panel.
- Safely applied to the user-level launcher copy without mutating distribution-managed files.
- Dedicated reset action (↺) to restore the original launch command at any time.

### 📦 AppImage Discovery & Safe Lifecycle
- Surfaces unregistered AppImages located in `~/Applications` as registration candidates for explicit, user-confirmed desktop integration.
- **Add AppImage Action**: Register external AppImages into your desktop grid with a clear preview showing source, destination, and desktop file names.
- **Safe Copy Policy**: Copies external AppImages into `~/Applications` using atomic writes, preserving the original external file untouched.
- **In-place Support**: If an AppImage is already in `~/Applications`, it is registered in-place.
- **Safe Unregistration**: Remove desktop launchers and extracted icons cleanly from within Glyph while preserving the underlying executable binaries.
- **Explicit Self-Registration**: Running Glyph from an AppImage provides a menu action to register Glyph into the desktop app grid without silent, unexpected first-run changes.

### 💡 Informational Install & Update Guidance
- Contextual, source-aware guidance explaining how applications from each package source are typically installed and updated on Linux.
- Distribution-first instructions prioritizing native package managers (DNF on Fedora, Flatpak, APT, Pacman, Snap, and AppImage).
- Quick launch button to open your desktop Software center when available.
- Purely educational: never executes unconfirmed package commands or downloads unverified packages.

### 🛡️ Baseline Safety, Conflict Protection & Artwork Cleanup
- **Managed Artwork Cleanup Prompts**: Reverting an application's custom icon, running bulk icon resets, or unregistering an AppImage now offers to permanently remove the cached artwork file from `~/.local/share/glyph/icons/` if it is uniquely owned and unmodified.
- **Smart Asset Retention**: If an icon file has been modified externally, is missing a cryptographic checksum, or is shared across multiple application entries, Glyph automatically keeps the file on disk to prevent accidental data loss.
- **External Launcher Conflict Protection**: When customizing an application whose local desktop file was modified outside of Glyph, an informative conflict dialog offers to preserve your changes or rebase against external modifications.
- **Theme Icon Support in Bulk Revert**: "Revert All Custom Icons…" seamlessly detects and resets both semantic theme icon references and custom image files back to the desktop baseline.
- **Journal Hygiene**: Clean startup detection and automated recovery ensure write-ahead journal state remains resilient across application upgrades.

### 🛠️ AppImage Packaging & System Fixes
- Staged icons to matching resolution directories (`1024x1024` and scalable) and included a valid AppImage `.DirIcon`.
- Corrected AppImage desktop launcher execution to avoid depending on bare `Exec=glyph` on host `PATH`.

- **GTK**: `>= 4.10`

- **PyGObject**: `>= 3.42`
- **Desktop Environment**: GNOME Shell, KDE Plasma, COSMIC, Cinnamon, XFCE, or MATE.
